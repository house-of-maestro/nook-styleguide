# Figma → website variable sync

The source of truth is now the committed Figma export in `design/figma-variables.json`. Every Vercel build runs `npm run tokens:sync` first. That generates `src/tokens.css` and refreshes the styleguide inventory while preserving its component list. Website components use the generated color, font, spacing, radius, layout and typography tokens. Responsive overrides remain intentional web behavior.

## Your regular workflow — no Enterprise subscription needed

1. Change variables or text styles in the **Nook Library** Figma source file.
2. Run **Nook — Export website variables** (one-time installation below).
3. Click **Prepare website variables → Download figma-variables.json**.
4. Open [the export folder on GitHub](https://github.com/house-of-maestro/nook-styleguide/tree/main/nook-styleguide/design). Choose **Add file → Upload files** and upload the downloaded JSON into this same folder, replacing the existing `figma-variables.json`. Avoid uploading the outer folder or a renamed file such as `figma-variables (1).json`.
5. For a preview before publishing, choose **Create a new branch for this commit and start a pull request**. Vercel will build a preview using the new values; review its website and `/styleguide`, then merge to publish. Committing directly to main publishes immediately after a successful Vercel build.

No stylesheet editing, access token, or plugin subscription is needed. Merely editing Figma does not push a deployment: export and upload the values you want to publish. GitHub Actions checks the export and Vercel independently validates it during its build. If validation fails, the deployment fails instead of publishing partial or invalid tokens.

You can also ask Codex: **“Sync the latest Nook variables and text styles from Figma.”** It can use the existing Figma connection to refresh the export and propose the code update, without the Enterprise REST API.

## Install the exporter once

1. Download the repository ZIP from GitHub (**Code → Download ZIP**) and unzip it.
2. In the **Figma desktop app**, open your Nook Library.
3. Open **Plugins → Development → Import plugin from manifest…** (you can search for this action in Figma).
4. Choose `nook-styleguide/figma-exporter/manifest.json` from the downloaded repository.
5. Run **Plugins → Development → Nook — Export website variables**.

If Figma asks for a plugin ID when importing, use **Plugins → Development → New plugin**, choose a plugin with a custom UI, and create it in a new folder. Copy the supplied `code.js` and `ui.html` into that folder, replacing the generated files. Keep the manifest generated by Figma, which contains your own plugin ID. Then run that development plugin.

The exporter is read-only and has no network access. It exports local variable collections, all their modes, and local text styles. Open the source library, not a consuming design file. It does not export or replace component implementations.

## What is synced

- Colors, including the highlight: `colors/color-highlight` → `--colors-color-highlight` → `--nook-highlight`.
- Spacing, radius and layout variables; existing components consume the applicable tokens. Some exported primitives remain available for future use rather than being applied indiscriminately.
- Font family/weight variables and text style metrics. Besley, Mona Sans and Young Serif are installed; new font families must have their font assets added before publishing.
- Website styleguide values and text samples.

The current collection is **Primitives**, mode **Value**. Select a different mode in `selectedModes` in `scripts/sync-tokens.mjs` before using one. Cross-collection local aliases are resolved in each target collection's selected/default mode. Missing aliases, duplicate CSS names, missing required tokens, invalid values, and unsupported fonts stop the build. Multiple theme switching is not configured. Raw source values remain in the export; the styleguide inventory contains the resolved selected values. Components and their Code Connect mappings stay in place.

Never edit generated `src/tokens.css` directly; the next build will overwrite it.

## Optional: a GitHub button that fetches Figma directly

Figma currently restricts the Variables REST API to a Full seat in an Enterprise organization. See [Figma Variables API requirements](https://developers.figma.com/docs/rest-api/variables/).

If eligible:

1. Generate a Figma personal access token with `file_variables:read` and access to the Nook source file. Do not paste it into code, chat or a public file.
2. Save it in this repository's **Settings → Secrets and variables → Actions → New repository secret**, named `FIGMA_ACCESS_TOKEN`.
3. Under **Settings → Actions → General → Workflow permissions**, allow GitHub Actions to create pull requests if your organization permits it.
4. Open **Actions → Sync Figma variables (Enterprise API) → Run workflow**. It reads the current variables, validates/builds, and opens a review pull request when values have changed. It does not merge or publish automatically.

This API path updates variables only; export with the plugin to refresh text styles too. It is manual, not scheduled. No token is needed for the export/upload workflow above.

## Developer commands

```sh
npm run tokens:sync   # regenerate from the committed export
npm run tokens:check  # verify generated outputs match the export
npm run test:tokens   # conversion/alias/validation tests
npm run tokens:fetch  # optional Enterprise API; uses FIGMA_ACCESS_TOKEN
npm run build        # sync tokens, check TypeScript, build
```
